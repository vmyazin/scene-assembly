# Ideogram 4.6 and Precise Edit on Runware, and the Nov 30 sale ends

Status: Implemented, awaiting review

## Context

Runware released Ideogram 4.6 and Ideogram 4.6 Precise Edit on 2026-11-19. The
app had no Ideogram model outside Kie's older V3. Two dated sales stored on
2026-11-19 (HeyGen Video 1.0 on Runware, Seedance 2.5 Flash on Atlas) close on
2026-11-30, so this change also checks that every price surface returns to
list when they do.

## Goals

- Both models on Runware, wired like the existing Runware image models, with a
  quality control, because quality is what the price follows.
- Every id, parameter and price read from Runware's public pages on
  2026-11-23. No credentials, no generation, no paid request.
- An estimate never understates the published rate.
- Proof, under a mocked clock, that both sales flip to list at their end.

## Non-goals

No change to a provider default. No transparent background, magic prompt, seed,
mask or edit-region control. No Ideogram on fal. No change to how a Runware job
is priced for an agent: Runware reports the charge after the run, so the
estimate stays unknown there, as it is for every Runware job.

## Scope and implementation boundary

- Entries: `ideogram46()` in `lib/providers/catalog.ts`, with
  `resolveImageQuality` and `imageSizesForQuality` beside it.
- Types: `qualities` on `ProviderModel`, `quality` on `ImageRequest`,
  `usdByQuality` and `pixelTiers` on `ProviderRate` (`lib/providers/types.ts`).
- Pixels: `RUNWARE_IDEOGRAM_46_DIMENSIONS` and `runwareDimensionTable` in
  `lib/providers/output-size.ts`.
- Request: `imageTask` in `lib/providers/runware.ts`.
- Price: `resolveCatalogRate` in `lib/spend/resolve.ts`.
- Surfaces: `components/GenerationInterface.tsx` (Quality chip, estimate),
  `app/api/generate/route.ts`, `cloud/src/provider-adapters/aggregators.ts`,
  `lib/account/model-schema.ts`, `lib/models/listbox-specs.ts`.
- Sales: `lib/providers/model-promotions.ts`, `lib/providers/use-sale-clock.ts`,
  one call in `components/ProviderVideoWorkspace.tsx`.

Not touched: every other catalog entry, the Atlas, Comet, fal, Kie and Gemini
adapters, `lib/spend/account.ts`, `lib/spend/capture.ts`.

Neither page shows a sale (the HeyGen page does, in the same component), so

The 4.19 MP boundary is 2048 × 2048 = 4,194,304: the page's own 2048×2048
example is billed $0.06, the medium 2K rate, and Precise Edit names 4,194,304
as the very-low ceiling. Its 4096×2304 text example is $0.12 and its 3072×2048
reference example is $0.20, which match the 4K rows.

## Decisions

**Precise Edit is its own entry, not a mode.** It is a separate vendor id with
a different input field and no dimensions. Every other edit variant in this
catalog is its own entry for the same reasons (Qwen-Image-Edit-Plus here, and
each Atlas `… Edit`). It lists `modes: ['image']`, `imageInput: 'seed'` and an
empty `aspectRatios`, which is how MAI-Image-2.6 Edit already says "the request
carries no shape".

**Quality is a catalog list, like `backgrounds`.** `qualities` names the
options and the default. The request always writes `settings.quality`, so the
vendor's default never decides what a run costs.

**The default quality is medium.** It is the vendor's default, so a request
that names no quality (an agent that leaves the field out, a saved selection
from before the control existed) costs what the card shows. Low is half the
price and one press away. GPT Image 2.6 on Kie set the same precedent.

**Very low stops at 2K.** The page caps it at 4.19 MP. While it is selected,
4K leaves the size list and the size returns to 2K. The Worker refuses the
combination with a sentence that names it, and the adapter falls back to the
2K pair, so no path sends a size the vendor would reject.

**Sizes are the two price tiers.** 2K (the default) and 4K, each with one pixel
pair per shape. Every 2K pair is at or under 4,194,304 pixels and every 4K pair
is above it, so the tier on the card is the tier billed. Every pair is on the
32-pixel grid and is exactly the ratio it is named for.

**Both rate tables are stored.** `rate` is text to image and `referenceRate` is
image to image; `resolveCatalogRate` now reads `referenceRate` for an image
model's `image` mode. Nothing had to be approximated.

**Precise Edit is priced from the first image's pixels.** The result keeps the
source's size, so the tier follows `width × height` of the first reference,
which the tray already measures. Until it is measured, and anywhere it is not
known, the figure is the dearer tier and the cost line reads "Up to", not
"Est. ≈". A very-low edit is one price.

**The ledger is not estimated.** Runware returns the charge with the image
(`includeCost`), and both ledgers file that figure as exact. The table above
feeds only the cost line under the Generate button. An agent's
`estimate_cost` stays unknown for Runware, so a default grant still refuses
it, the same as every other Runware model.

**Five references.** 4.6 takes five and Precise Edit takes a source plus four,
so the Runware cap moves from 4 to 5 in the adapter, the Worker validator and
the agent schema. The older models keep their own `maxInputImages` of 1, 3
or 4.

## Not offered

- `settings.magicPrompt`. It is refused once reference images are attached, so
  the adapter never writes it in either mode. The vendor's own default applies
  to a text run.
- `settings.background` (transparent). `backgrounds` would carry it, but the
  Runware adapter has no background or `outputFormat` handling and the Worker
  accepts `background` for Atlas only.
- `inputs.maskImage` and the `settings.editRegion` box. No Runware image model
  here has a mask input, and a mask has to match the source's exact size.
- `seed`, `numberResults` above 1.
- Ideogram 4.6 on fal.

## The Nov 30 sale ends

| Sale | Stored end before | Published end | Now |
| --- | --- | --- | --- |
| Runware HeyGen Video 1.0, 50% | 2026-12-01 00:00 UTC | The page says "until November 30, 2026" and its script removes the notice once `expiresAt = "2026-11-30T23:00:00.000Z"` has passed | **2026-11-30 23:00 UTC** |
| Atlas Seedance 2.5 Flash, 35% | 2026-11-30 15:59 UTC | Banner "ends Nov 30", countdown `endAt: 1796054340000` | unchanged |

Two things were wrong, and both are fixed here.

1. **HeyGen ended an hour late.** The window was written from the visible
   text, which names no timezone. The page carries the instant, and it is
   23:00 UTC. For the last hour of Nov 30 the estimate, the picker and
   `list_models` would have shown half the price Runware's page shows. The
   window now ends at the published instant, the rule already used for Atlas.
2. **An open tab kept the sale price.** `withModelSale` answers for the moment
   it is asked, so every render is right, but nothing re-renders a video
   workspace left open across the end. `useSaleClock` arms one timer for the
   next boundary (`nextPromotionBoundary`) and re-renders when it passes.

Everything else already resolved at call time. Traced:

| Surface | Where | How it reads the sale |
| --- | --- | --- |
| Picker row price | `ProviderVideoWorkspace` → `providerVideoSpecs(withModelSale(model))` | Per render, now also at the boundary |
| Model note, estimate under the button | `selectedModel = withModelSale(…)` | Per render, now also at the boundary |
| Browser ledger | `captureProviderJob` | `withModelSale(model, job.createdAt)`; HeyGen files Runware's reported cost |
| Account ledger | `buildAccountSpendEntry` | `withModelSale(model, pricedAt ?? at)` |
| Agent `list_models` | `describeModels` | Called per request |
| Agent `estimate_cost`, budget | `estimateCloudJob` | `at: Date.now()` per request |
| Defaults | `DEFAULT_MODELS` | Neither model is a default, so no default was chosen on a sale price |

The catalog stores list prices and no module computes a sale price at import.
`saleCopies` caches a re-priced copy per model, and returns it only while the
window is open.

Tests: `tests/spend/promo-flip.test.tsx` moves a fake clock across both ends
and reads the estimate, the picker cell, the price, the note, the agent
estimate and both ledgers through `Date.now()`, never an `at` argument.
`cloud/tests/ideogram-4-6.test.ts` does the same through a real MCP client.

## Could not verify

- Either id by a real request. None was sent.
- That Runware bills what the tables say. The ledger uses the reported cost.
- Which side of the boundary exactly 4,194,304 pixels falls on, beyond the
  page's one 2048×2048 example at the 2K rate.
- Whether a Precise Edit of a source above 4.19 MP at `editRegion: auto` is
  billed at the 4K rate or by the region sent. It is estimated at the 4K rate.
- Whether the image-to-image rate applies to any run with reference images.
  The page has two tables and one reference example ($0.20 at 3072×2048), and
  that reading matches it.
- What `settings.magicPrompt` defaults to. The page lists no default.
- That the HeyGen sale price stops being charged at 23:00 UTC. That is when
  the page stops showing it.
- What Atlas charges for Seedance 2.5 Flash after its sale. "Up from 20%"
  suggests a smaller discount may return. List is the estimate until it is read.
- Which sale Atlas's second countdown (`1795708740000`, 2026-11-26 15:59 UTC)
  belongs to. It is not attached to the Seedance 2.5 Flash banner.
