# Seedream 5.5 on Atlas

Status: Approved design

## Context

ByteDance released Seedream 5.5 on 2026-11-09 and took it to general availability
on 2026-11-10. It replaces Seedream 5.0 Pro as the current Seedream: one model
family for text-to-image and reference editing, three size tiers, native
transparent output. The request was to add it as the default Seedream, keep 5.0
Pro selectable, and put it on Runware unless Atlas was confirmed cheaper.

## Goals

- Seedream 5.5 and Seedream 5.5 Edit are the first Seedream entries in the
  Atlas image list. Seedream 5.0 Pro, 5.0 Pro Edit and 5.0 Flash stay selectable.
- The size control offers 2K, 1.5K and 1K, and the estimate and both ledgers
  price the tier that is sent.
- Every input image on an edit is billed, the first included.

## Non-goals

No change to a provider default (`DEFAULT_MODELS` stays FLUX schnell on Atlas
and Z-Image Turbo on Runware). No migration of a saved model. No Seedream 5.5 on
Runware. No layer decomposition, Seedance 2.5 Flash or HeyGen Video. No change
to Kie's Seedream 5 Pro entry.

## Scope and implementation boundary

The entries are `seedream55()` in `lib/providers/catalog.ts`. The body is the
`isSeedream55` branch of `atlasImageFields` in `lib/providers/atlas.ts`. The
pixel table is `ATLAS_SEEDREAM_55_DIMENSIONS` in `lib/providers/output-size.ts`.
`ProviderRate.inputImageUsd` and its branch in `resolveCatalogRate`
(`lib/spend/resolve.ts`) are the only pricing code. `lib/spend/rates.ts` is not
touched: it holds Gemini and fal tables, and aggregator rates live on the
catalog entry. `store/useAppStore.ts` is not touched.

## Decisions

**Atlas, not Runware.** Atlas's quote is 20% under Runware's published rate at
every tier ($0.016 against $0.02, $0.028 against $0.035, $0.0064 against $0.008
per input). Runware's page also marks the model `coming-soon`, so a Runware
entry could not be the default Seedream today. There is no second copy on
Runware.

**The calculator quote is the rate.** The 2026-11-03 Atlas spec already settles
this: a headline that disagrees with the calculator is not the catalog rate.
Here the page's SKU table is the list price and the calculator applies a
discount to it. Seedream 5.0 Pro is priced the same way. `SEEDREAM_55_LIST_USD`
keeps the list figures beside the entry, and a test holds the rate at 80% of
them, so ending the discount is a one-line change.

**The $0.016 on Atlas's page is the same number.** The page's metadata, its
schema.org offer and the playground line all print $0.016 with no size. That is
the discounted lower tier, a "from" price. It does not apply to 2K, which the
calculator quotes at $0.028.

**`inputImageUsd`, not `extraInputImageUsd`.** 5.0 Pro includes the first input
and charges $0.003 for each one after it. 5.5 charges every input. One field
with a flag would give one of the two the other's first-image rule, so the rate
type has two fields and `resolveCatalogRate` has two branches.

**2K is the first size.** It is the vendor default. A request with no size (an
agent that omits `resolution`) sends `2048*2048` and is priced at 2K. The studio
always has a size on its chip, starting from the shared 1K, and sends and prices
that.

**No migration.** `atlasImageModel` has defaulted to FLUX schnell since the
field was added, no selector writes a Seedream id without a click on that row,
and no provider default was ever a Seedream id. A stored 5.0 Pro id is a choice.
The persist version stays 4.

## Not verified

- No live generation. The body is checked against the schema with a mocked
  `fetch`.
- That Atlas bills the calculator's figure. The calculator is the only public
  quote; an account's invoice is the proof.
- How long the discount lasts. The calculator returns no end date.
- The host a finished 5.5 image is served from. `lib/account/result-location.ts`
  already allows Atlas's CDN and ModelArk's bucket; a different host would end a
  background job at `result_location` and needs one allow-list line.
